## Задание 2. Циклы и базовые алгоритмические схемы

### Статистика за один проход
Функция `analyze` за один цикл считает сумму, минимум, максимум и количество четных. Среднее становится известно только после первого прохода, поэтому значения выше среднего считает отдельная функция `count_above_mean` (второй проход). `min()`, `max()`, `sum()` и `list.count()` не используются.

```text
Сумма: 144
Минимум: 7, максимум: 21
Четных значений: 4
Среднее: 14.4, значений выше среднего: 6
```

Проверка вручную: четные это 12, 18, 18, 18 (4 штуки); выше 14.4 это 15, 18, 18, 21, 15, 18 (6 штук).

### Линейный поиск
Функция `linear_search` идет по списку и возвращает индекс первого вхождения, если числа нет, то `-1`. Для `18` результат `3`, для `12` результат `0`, для `100` результат `-1`.

### Проверка простоты
```python
def is_prime(n):
    if n < 2:
        return False
    d = 2
    while d * d <= n:
        if n % d == 0:
            return False
        d += 1
    return True
```
Условие `d * d <= n` равно `d <= sqrt(n)`, но без вычисления корня и без ошибок округления float. Проверено на числах 1, 2, 3, 4, 17, 25, 49, 97, 100, 7919.

### Сложность алгоритмов

| Алгоритм | Время | Память | От чего зависит |
|---|---|---|---|
| Статистика за один проход | O(n) | O(1) | n - длина списка |
| Подсчет выше среднего | O(n) | O(1) | n |
| Линейный поиск | O(n) в худшем, O(1) в лучшем | O(1) | n и позиция искомого |
| Проверка простоты | O(sqrt(N)) | O(1) | значение числа N, а не количество цифр |
| Сортировка выбором | O(n^2) | O(n) (копия списка), сама сортировка O(1) | n |
| Бинарный поиск | O(log n) | O(1) | n |

**Почему достаточно делителей до sqrt(N):**
Если N = a * b, то один из множителей не больше другого, то есть `a <= sqrt(N)`. Значит, если у числа есть делитель больше корня, то есть и парный делитель меньше корня (или равный). Поэтому если до корня делителей нет, то их нет вообще, и число простое. Корень берется включительно, так как для квадрата простого числа (например 49 = 7 * 7) единственный делитель как раз равен корню.

### Псевдокод
**Бинарный поиск:**
```text
left = 0, right = длина - 1, comparisons = 0
пока left <= right:
    mid = (left + right) // 2
    comparisons += 1
    если a[mid] == target: вернуть mid
    иначе если a[mid] < target: left = mid + 1
    иначе: right = mid - 1
вернуть -1
```

**Сортировка выбором:**
```text
для i от 0 до n-2:
    min_index = i
    для j от i+1 до n-1:
        если a[j] < a[min_index]: min_index = j
    поменять a[i] и a[min_index]
```

### Практическое расширение: сравнение поисков
Для каждого n генерируется набор случайных чисел (`random.Random(42)`), сортируется своей сортировкой выбором (результат проверен через `sorted`), после чего на одном и том же отсортированном списке запускаются оба поиска. Ищется самый последний элемент (худший случай для линейного поиска) и отсутствующее число `-1`. За одно сравнение в бинарном поиске считается одна итерация (элемент в середине сравнивается с искомым).

| n | Сортировка выбором | Линейный (последний) | Бинарный (последний) | Линейный (нет) | Бинарный (нет) |
|---|---|---|---|---|---|
| 10 | 45 | 10 | 4 | 10 | 3 |
| 100 | 4950 | 100 | 7 | 100 | 6 |
| 1000 | 499500 | 1000 | 10 | 1000 | 9 |

Видно, что линейный поиск растет пропорционально n (в 10 раз больше данных, в 10 раз больше сравнений), а бинарный только на 3 сравнения при росте n в 10 раз, то есть логарифмически. Сортировка выбором всегда делает n(n-1)/2 сравнений (45, 4950, 499500), поэтому для одного поиска сортировать не выгодно, а для многих поисков по одним данным выгодно.

## Задание 3. Коллекции и выбор структуры данных

Все данные хранятся в одном словаре `data` с пятью структурами:
* `students` - множество студентов;
* `labs` - множество лабораторных;
* `attempts` - словарь `студент -> список результатов попыток`;
* `best` - словарь `(студент, лаба) -> лучший результат`;
* `count` - словарь `(студент, лаба) -> число попыток`.

```text
Студенты: ['anna', 'boris', 'daria']
Лабораторные: ['lab_01', 'lab_02']
Попытки по студентам: {'anna': [5, 5, 4], 'boris': [4, 5], 'daria': [3]}
Лучшие результаты: {('anna', 'lab_01'): 5, ('boris', 'lab_01'): 4, ('anna', 'lab_02'): 5, ('daria', 'lab_01'): 3, ('boris', 'lab_02'): 5}
Число попыток: {('anna', 'lab_01'): 2, ('boris', 'lab_01'): 1, ('anna', 'lab_02'): 1, ('daria', 'lab_01'): 1, ('boris', 'lab_02'): 1}
Сдавали обе работы: ['anna', 'boris']
```

Студенты, сдавшие обе работы, находятся пересечением двух множеств: `{s для lab_01} & {s для lab_02}`. До добавления записей это `anna` и `boris`.

### Добавление записи без перестройки
Функция `add_submission(data, record)` обновляет все пять структур за один вызов: добавляет в множества, делает `setdefault(...).append(...)` для попыток, обновляет лучший результат, если новый больше, и увеличивает счетчик. После добавления `("daria", "lab_02", 4)` и `("boris", "lab_01", 5)`: лучший результат `boris` по `lab_01` стал 5, число его попыток 2, а обе работы теперь сдали `anna`, `boris` и `daria`.

### Почему именно такие структуры
* **Множество** хранит только уникальные элементы, повторное добавление ничего не меняет. Поэтому студент, который сдавал работу три раза, в множестве студентов один раз. Проверка `x in set` и добавление работают за O(1) в среднем (хеш-таблица).
* **Кортеж можно использовать как ключ словаря**, потому что он неизменяемый и его хеш не меняется, пока он существует (если все его элементы тоже хешируемы, а `("anna", "lab_01")` состоит из строк).
* **Список нельзя использовать как ключ**, потому что он изменяемый: если бы его содержимое поменялось, то поменялся бы хеш, и словарь не нашел бы элемент. Поэтому Python выдает `TypeError: unhashable type: 'list'`.
* **Словарь лучше списка для поиска по составному ключу**: в списке кортежей пришлось бы перебирать все записи (O(n)), а в словаре ключ `(student, lab)` ищется по хешу за O(1) в среднем.

### Сложность операций

| Коллекция | Добавление | Поиск |
|---|---|---|
| list | O(1) в конец (амортизированно) | O(n) |
| tuple | нельзя изменять | O(n) по значению, O(1) по индексу |
| dict | O(1) в среднем | O(1) в среднем |
| set | O(1) в среднем | O(1) в среднем |

В худшем случае (много коллизий хешей) операции со словарем и множеством могут стать O(n), но на практике этого не происходит.

### Практическое расширение: текстовые запросы
Команда делится через `split()` на команду и аргументы, дальше `match / case` выбирает операцию (с проверкой числа аргументов через `if` в `case`). На неизвестную команду, пустую строку, неверное число аргументов и отсутствующий ключ программа выводит сообщение и не падает.

## Задание 4. Функции, параметры и области видимости

### Функции
* `arithmetic_mean(values)` - среднее, для пустого списка ранний `return 0.0`.
* `normalize_name(name)` - `split()` убирает лишние пробелы, `capitalize()` исправляет регистр каждой части, для пустой строки ранний `return ""`.
* `build_report(student, results, *, precision=2, prefix="Результат")` - `precision` и `prefix` только именованные из-за `*`. Для пустого `results` ранний `return` с сообщением "нет результатов".
* `collect_tags(*tags, lowercase=True)` - убирает пробелы, пустые значения и повторы, порядок сохраняется, возвращает кортеж.

Исходные коллекции внутри функций не меняются (проверено `assert`: список до и после вызова одинаковый). Для каждой функции написано от 3 до 4 проверок через `assert`, все проходят.

### Вызовы и распаковка
```python
build_report("иванов иван", [5, 4, 4])
# Результат: Иванов Иван, среднее 4.33, работ 3
build_report("иванов иван", [5, 4, 4], precision=1, prefix="Итог")
# Итог: Иванов Иван, среднее 4.3, работ 3

args = ["петров пётр", [3, 4, 5]]
kwargs = {"precision": 0, "prefix": "Оценка"}
build_report(*args, **kwargs)
# Оценка: Петров Пётр, среднее 4, работ 3
collect_tags(*["a", "B", "a"])
# ('a', 'b')
```
`*args` раскладывает список в позиционные аргументы, а `**kwargs` раскладывает словарь в именованные.

### Исследование LEGB
```python
course = "Python"                  # G

def outer():
    attempts = 0                   # E
    topic = "функции"              # E
    def inner():
        nonlocal attempts
        attempts += 1
        message = f"{course}, {topic}, попытка {attempts}"
        return message, len(message)
```

Схема областей видимости:
```text
Built-in:  len, print, ...
  Global:  course, outer, ...
    Enclosing (outer):  attempts, topic, inner
      Local (inner):    message
```

Порядок поиска имен в `inner` (Local -> Enclosing -> Global -> Built-in):
* `message` - найдено сразу в **L** (создается в `inner`).
* `attempts` - в **L** нет (из-за `nonlocal` оно не создается локально), находится в **E** (в `outer`) и там же изменяется.
* `topic` - в **L** нет, найдено в **E**.
* `course` - нет в **L**, нет в **E**, найдено в **G**. Только читается, глобальное значение не меняется (после вызова остается `Python`).
* `len` - нет в **L**, **E**, **G**, найдено в **B** (встроенные имена).

Вывод программы: `Python, функции, попытка 1`, `Python, функции, попытка 2`, после `outer()` значение `attempts` равно 2.

### Ошибка изменяемого значения по умолчанию
```python
def add_result(value, results=[]):
    results.append(value)
    return results
```
Значение по умолчанию (пустой список) создается **один раз**, когда выполняется инструкция `def`, а не при каждом вызове. Оно хранится в самой функции. Поэтому все вызовы без второго аргумента работают с одним и тем же списком, и он накапливает значения: после трех вызовов `add_result(1)`, `add_result(2)`, `add_result(3)` все три результата указывают на один список `[1, 2, 3]`.

Исправление: в качестве значения по умолчанию использовать `None`, а новый список создавать внутри функции:
```python
def add_result(value, results=None):
    if results is None:
        results = []
    else:
        results = list(results)
    results.append(value)
    return results
```
После исправления вызовы дают `[1]`, `[2]`, `[3]`, а переданный список не изменяется (`add_result(20, [10])` дает `[10, 20]`, исходный остается `[10]`).

### Практическое расширение
`apply_to_results(operation, values)` возвращает новый список с результатами применения функции к каждому значению. Передавались именованная функция `square` и `lambda x: x + 5`:
```text
[2500, 4225, 6400, 9025]
[55, 70, 85, 100]
```
Фабрика `make_threshold_checker(threshold)` возвращает вложенную функцию `check(score)`. Созданы две независимые проверки:
```text
порог 60: [False, True, True, True]
порог 90: [False, False, False, True]
```
В замыкании сохраняется **значение `threshold`**, которое было на момент создания (60 у первой функции и 90 у второй). Каждый вызов фабрики создает отдельную область видимости, поэтому проверки не влияют друг на друга.

| 5 | Студент без результатов | `{"Ира": [], "Паша": [70]}` | у Иры `None` и "нет данных", лидер Паша, среднее группы 70 | совпало | OK |
| 6 | Границы категорий | 90, 89.99, 75, 74.99, 60, 59.99, 0, 100 | отличный, хороший, хороший, удовлетворительный, удовлетворительный, недостаточный, недостаточный, отличный | совпало | OK |

Также проверено, что исходный словарь `students` после анализа не изменился (сравнение с копией).

### Контракты функций

| Функция | Вход | Результат | Особые случаи |
|---|---|---|---|
| `mean(values)` | список чисел | `float` | пустой список -> `None` |
| `minimum(values)` | список чисел | наименьшее число | пустой список -> `None` |
| `maximum(values)` | список чисел | наибольшее число | пустой список -> `None` |
| `classify(score)` | число 0-100 (может быть дробным) или `None` | строка категории | `None` -> "нет данных"; 89.99 -> "хороший" |
| `student_summary(name, results)` | имя и список результатов | словарь `name, count, mean, min, max, category` | пустой `results` -> `None` и "нет данных" |
| `group_summary(students)` | словарь `имя -> список` | словарь со списком итогов студентов, числом студентов, средним группы и счетчиком категорий | пустая группа -> `group_mean = None`, все счетчики 0 |
| `find_top_students(students)` | словарь `имя -> список` | список имен с наибольшим средним | пустая группа или все без результатов -> `[]`; при равенстве несколько имен |
| `format_report(student_data, group_data)` | результаты `student_summary` и `group_summary` | многострочный текст | `group_mean = None` -> "нет данных" |

Рейтинг делает вспомогательная функция `make_rating(students)`: она возвращает новый отсортированный список пар `(имя, среднее)` и не меняет исходный словарь.

### Декомпозиция
Программа разбита на три уровня. Нижний - простые функции для чисел (`mean`, `minimum`, `maximum`, `classify`), они ничего не знают про студентов. Средний - `student_summary` собирает итоги одного студента из этих функций, а `group_summary` и `find_top_students` работают со всей группой. Верхний - `format_report` только превращает готовые данные в текст и ничего не считает. Так любую часть можно проверить отдельно (например, `classify` на границах), а правило для пустого списка реализовано в одном месте - в `mean`, `minimum` и `maximum`.

### Сложность
Пусть S - число студентов, N - общее число результатов. `student_summary` делает три прохода по списку студента, `group_summary` вызывает его для каждого студента, поэтому построение общей статистики занимает **O(N + S)** по времени (константа 3 не важна). Память O(S) для хранения итогов. Рейтинг дополнительно делает сортировку за O(S log S). Поиск лидеров один проход по студентам, но среднее считается заново для каждого студента, поэтому O(N).
