## Задание 1. От исходного кода к байткоду

### Часть 1. Режимы запуска
В REPL результат выводится сам по себе, потому что эта консоль создана для быстрой проверки кода. При запуске файла (скрипта) код просто выполняется "под капотом", и чтобы мы увидели результат, нужно явно написать функцию `print`: `print(2 + 3 * 4)`.

### Часть 2. Выражения и инструкции
* **Выражения** (то, что можно вычислить): `4 * 2`, `f"{course}: {hours} часов"`, `"Python"`.
* **Инструкции** (то, что просто выполняет действие): `course = "Python"`, `hours = 4 * 2`, `print(f"{course}: {hours} часов")`.
* **Литералы** (конкретные значения в коде): `"Python"`, `4`, `2`.
* **Имена** (переменные): `course`, `hours`.

### Часть 3. AST и байткод
**Версия Python:** 3.13.9

Фрагмент AST дерева (`python -m ast task_1.py`):
```python
Module(
    body=[
        Expr(
            value=Call(
                func=Name(id='print', ctx=Load()),
                args=[
                    BinOp(
                        left=Constant(value=2),
                        op=Add(),
                        right=BinOp(
                            left=Constant(value=3),
                            op=Mult(),
                            right=Constant(value=4)))])),
        Assign(
            targets=[
                Name(id='course', ctx=Store())],
            value=Constant(value='Python'))...
```

Фрагмент байткода (`python -m dis task_1.py`):
```text
0	RESUME	0
2	LOAD_NAME	0 (print)
	PUSH_NULL
	LOAD_CONST	0 (14)
	CALL	1
	POP_TOP
5	LOAD_CONST	1 ('Python')
	STORE_NAME	1 (course)
```

**Анализ AST и байткода:**
По дереву AST видно, как питон разбивает наш код на узлы: `Assign` — присваивание переменной, `BinOp` — бинарные операции (математика), `Call` — вызов функции. В байткоде видны конкретные инструкции: `LOAD_CONST` загружает константу, а `STORE_NAME` сохраняет ее в переменную. Интересно, что питон оптимизировал `2+3*4` и в байткоде сразу лежит результат `14` (`LOAD_CONST 0 (14)`).

**Контрольный вопрос:**
Байткод нельзя назвать машинным кодом процессора, потому что процессор компьютера его не поймет. Байткод выполняется виртуальной машиной самого питона (CPython).

## Задание 2. Имена, объекты и сравнение

**Прогнозы до запуска:**
```python
print(a == b)  # True
print(a is b)  # True
print(a == c)  # True
print(a is c)  # False
```

**Схема связей:**
* Имя `a` указывает на объект `int(1000)` по адресу `X`.
* Имя `b` указывает на тот же самый объект `int(1000)` по адресу `X` (потому что мы написали `b = a`).
* Имя `c` указывает на другой объект `int(1000)` по адресу `Y` (он создан заново через `int("1000")`).

**Разница между `==` и `is`:**
Оператор `==` сравнивает сами значения внутри переменных (например, числа 1000 и 1000). А оператор `is` проверяет, лежат ли они в одном и том же месте в памяти (одинаковый ли у них `id`).

**Сформулированное правило:**
Сравнивать на `is` нужно только `None`. Для всего остального (чисел, строк и тд) надо использовать `==`.

**Контрольные вопросы:**
1. Инструкция `b = a` не создает копию. Она просто делает еще одну ссылку на тот же объект.
2. `type()` показывает тип данных, а `id()` показывает адрес объекта в памяти.
3. С `None` нужно использовать `is`, потому что объект `None` в памяти существует в единственном экземпляре.

## Задание 3. Числовые типы, операции и преобразования

* **Эксперимент A:** Деление `/` всегда возвращает `float` (чтобы случайно не отсечь дробную часть и не потерять точность). А `//` просто отбрасывает остаток и возвращает `int`.
* **Эксперимент B:** В питоне целые числа (`int`) могут быть любой длины, пока хватает оперативки. В других языках (типа С++) у них есть жесткий лимит, и они могут переполниться.
* **Эксперимент C:** `0.1 + 0.2` дает `0.30000000000000004`. Это из-за того, как дроби хранятся в двоичной системе в памяти компа (погрешность IEEE 754). Поэтому флоаты надо сравнивать через `math.isclose`.
* **Эксперимент D:** `bool("False")` дает `True`, потому что любая непустая строка в питоне считается `True`.

**Контрольные вопросы:**
1. Обычное деление дает `float`, чтобы не терять дробную часть при делении, например, 1 на 2.
2. `int("42")` переводит строку в число, а `int(42.9)` просто отбрасывает цифры после запятой.
3. Из эксперимента D falsy-значениями являются `0`, пустая строка `""` и результат `bool(0)`.

## Задание 4. Строки, Unicode и форматирование

1. Первый символ: `student[0]` (А). Последний: `student[-1]` (а).
2. Срезы: `student[0:4]` ("Анна"), `student[5:]` ("Смирнова").
3. Регистры: `student.upper()`, `student.lower()`.
4. Инициалы: `f"{student[0]}.{student[5]}."`
5. Обратный порядок: `course[::-1]`
6. Форматирование:
   * Оператор `%`: `"%s — %s: %d/%d (%.1f%%)" % (...)`
   * Метод `.format`: `"{} — {}: {}/{} ({:.1f}%)".format(...)`
   * f-строка: `f"{student} — {course}: {completed}/{total} ({percent:.1f}%)"`
7. Unicode: `len(symbol)` дает `1` (один символ). А `len(symbol.encode("utf-8"))` дает `2`, потому что кириллица занимает 2 байта в памяти.
8. При `student[0] = "X"` программа падает, потому что строки нельзя изменять.


**Контрольные вопросы:**
1. `len()` от строки считает просто количество букв, а от байтов — количество байт, которое нужно для их хранения.
2. В срезе `text[start:stop:step]` `start` — откуда начинаем, `stop` — до куда (не включая сам индекс), `step` — с каким шагом.
3. Строки нельзя менять (они immutable). Метод `.upper()` не меняет старую строку, а создает в памяти абсолютно новую.
